# Workspace backup and restore

Choose **Workspace backup → Export workspace** to download a `.marketweft.json` file. The export reads one committed catalog snapshot. It includes every imported series, including instruments removed from the watchlist, the selected instrument, watchlist order and SMA/EMA preferences. When the comparison pane is open, the export includes its instrument, overlays and UTC-link setting. Each series carries its source CSV text and its venue, symbol, bar interval, source label, usage grant and adjustment policy. The fixture data bundled with the app is identified by version and checksum.

To recover on another browser profile, open the terminal over HTTPS or localhost and choose **Workspace backup**. Select the file under **Backup file**. MarketWeft checks the format, checksums, sample compatibility, instrument identities, preferences, CSV values and record counts. The preview shows how many imported histories and bars the file contains, along with the selected instrument and watchlist count.

**Restore workspace** replaces the destination's imported histories and preferences in one transaction. Export the destination first to keep a copy. A verified backup with zero imported series also replaces the current import catalog. If another tab changes the workspace during review, choose the file again to review against its latest state. A failed or interrupted replacement leaves the previously committed catalog available.

A backup contains plain JSON, including the contents of imported CSV files. Keep backups in a location appropriate for those files and their usage grants. Checksums detect altered contents. Anyone able to edit the file can also compute new checksums.

## Format versions

A workspace with a saved close-change histogram or its interval uses version 40. A workspace with a saved baseline chart or baseline price uses version 39. A workspace with a saved close-area or step-line chart uses version 38. A workspace with saved price or time ranges uses version 37. A workspace with saved chart notes or arrows uses version 36. A workspace with saved ellipses or triangles uses version 35. A workspace with saved polylines or Fibonacci retracements uses version 34. A workspace with saved rectangles or parallel channels uses version 33. A workspace with saved horizontal rays or trend lines uses version 32. A workspace with saved price lines or UTC time markers uses version 31. A workspace with saved Aroon or Aroon Oscillator settings uses version 30. Saved CCI or ROC settings use version 29. Saved Directional Movement System settings use version 28. Saved MFI or VWMA settings use version 27. Saved Chaikin study settings use version 26. Saved On-Balance Volume or Accumulation/Distribution Line settings use version 25. Saved MACD settings use version 24. Saved Williams %R settings use version 23. Saved Stochastic Oscillator settings use version 22. Saved Keltner Channels settings use version 21. Saved Donchian Channels settings use version 20. Saved Bollinger %B or BandWidth settings use version 19. Settings for the Bollinger Bands price overlay use version 18. The shared pane study settings for RSI and ATR use version 17. A saved RSI-only pane setting in the earlier layout uses version 16. Without RSI settings, a saved recorded volume target uses version 15. Without a saved volume target, a saved recorded-range size uses version 14. Without a recorded-range size, a saved Point and Figure pane or custom box size uses version 13. Without Point and Figure settings, a saved Kagi pane or custom Kagi reversal size uses version 12. Without Kagi settings, a saved Three Line Break pane uses version 11. Without Three Line Break, a saved Renko pane or custom Renko brick size uses version 10. A saved Heikin-Ashi pane without Renko settings uses version 9 and can contain structured grants and verified provider histories. Without a Heikin-Ashi pane, version 8 takes precedence for verified provider histories and version 7 for structured grants. A saved OHLC bar choice uses version 6. A saved close line choice without OHLC uses version 5. Workspaces with custom moving-average periods use version 4 when both charts use candles. Earlier versions cover drawings (3), two-pane settings (2), and single-pane settings (1). MarketWeft validates and restores all forty formats. The comparison pane opens on restore when the backup contains its settings.

| Field | Contents |
| --- | --- |
| `format`, `version` | The string `marketweft-workspace` and integer `1` through `40`. |
| `manifest.sampleSet` | The built-in sample version and SHA-256 digest of the ordered sample identities, names and OHLCV values. |
| `manifest.preferences` | `selected`, `watchlist`, `sma` and `ema`. Watchlist entries must be unique catalog or sample IDs. The primary selection must be on the watchlist. |
| `manifest.preferences.comparison` | Required in version 2 and optional in versions 3 through 40. `selected` identifies an instrument. `sma`, `ema` and `linked` are Booleans. |
| `manifest.preferences.drawings` | Required in version 3 and optional in versions 4 through 40. Maps known instrument IDs to `start` and `end` objects. Each endpoint contains integer `time` in UTC Unix seconds and signed integer `ticks` in millionths. |
| `manifest.preferences.overlayPeriods` | Required in version 4 and optional in versions 5 through 40. Contains `primary`, `comparison` or both, with integer `sma` and `ema` periods from 1 through 100,000 bars. |
| `manifest.preferences.chartTypes` | Required in versions 5 and 6. Contains `primary`, `comparison` or both. Version 5 entries are `line`. Version 6 requires at least one `ohlc` entry and can also include a `line` entry. Versions 7 and 8 can include `line` or `ohlc`. Version 9 requires at least one `heikin-ashi` entry and can include either other type. Version 10 also permits `renko`. Version 11 requires at least one `three-line-break` entry. Version 12 also permits `kagi`. Version 13 also permits `point-and-figure`. Version 38 requires at least one `area` or `step-line` entry and permits the earlier chart types. Version 39 permits `baseline`. Version 40 permits `close-change`. Candles are the default for a pane without an entry. |
| `manifest.preferences.baselineTicks` | Optional in versions 39 and 40. Maps `primary` or `comparison` to signed integer millionths within ±2,000,000,000,000,000 ticks. A baseline pane without a saved reference uses zero. |
| `manifest.preferences.closeChangeSeconds` | Optional in version 40. Maps `primary` or `comparison` to a positive integer from 1 through 4,294,967,295 seconds. |
| `manifest.preferences.renkoTicks` | Optional in versions 10 through 40. Maps `primary` or `comparison` to a positive integer brick size in millionths of a price unit, up to 2,000,000,000,000,000 ticks. A Renko pane without an entry uses one price unit. |
| `manifest.preferences.kagiTicks` | Optional in versions 12 through 40. Maps `primary` or `comparison` to a positive integer reversal size in millionths of a price unit, up to 2,000,000,000,000,000 ticks. A Kagi pane without an entry uses one price unit. |
| `manifest.preferences.pointFigureTicks` | Optional in versions 13 through 40. Maps `primary` or `comparison` to a positive integer box size in millionths of a price unit, up to 2,000,000,000,000,000 ticks. A Point and Figure pane without an entry uses one price unit. |
| `manifest.preferences.rangeTicks` | Required in version 14 and optional in versions 15 through 40. Maps `primary` or `comparison` to a positive integer recorded range size in millionths of a price unit, up to 2,000,000,000,000,000 ticks. The trade file is selected during research. |
| `manifest.preferences.volumeTicks` | Required in version 15 and optional in versions 16 through 40. Maps `primary` or `comparison` to a positive integer target in millionths of a volume unit, up to 2,000,000,000,000,000 ticks. The trade file is selected during research. |
| `manifest.preferences.rsi` | Required in version 16 and optional in versions 17 through 40. Maps `primary` or `comparison` to `enabled` and integer `period` from 2 through 100,000 changes. A pane without an entry starts with RSI hidden and period 14. |
| `manifest.preferences.studies` | Required in versions 17 through 30 and optional in versions 31 through 40. Maps each configured pane to study keys `rsi` or `atr`, each with a Boolean `enabled` and integer `period`. Version 18 adds the `bb` key. Version 19 adds `bb_percent_b` and `bb_bandwidth`. Version 20 adds `donchian`. Version 21 adds `keltner` with EMA `period` and Wilder `atrPeriod`, both from 1 through 100,000. Version 22 adds `stochastic` with lookback `period`, %K `smoothPeriod` and %D `signalPeriod`, each from 1 through 100,000. Version 23 adds `williams_r` with a lookback from 1 through 100,000. Version 24 adds `macd` with fast `period`, `slowPeriod` and `macdSignalPeriod` from 1 through 100,000. The fast period must be shorter than the slow period. Version 25 adds `obv` and `adl`, each with an `enabled` flag. Version 26 adds `chaikin_money_flow` with a lookback `period` and `chaikin_oscillator` with fast `period` and `chaikinSlowPeriod`. Version 27 adds `mfi` and `vwma`, each with a lookback `period`. Version 28 adds `dmi` with the DI `period` and `adxPeriod`. Version 29 adds `cci` and `roc`, each with a lookback `period`. Version 30 adds `aroon` and `aroon_oscillator`, each with its own `period`. RSI accepts 2–100,000. ATR, all three Bollinger studies and Donchian Channels accept 1–100,000. Current study entries take precedence over legacy entries for the same pane and study. |
| `manifest.preferences.annotations` | Required in versions 31 through 37 and optional in versions 38 through 40. Maps known instrument IDs to nonempty arrays. Each entry has a unique UUID within its instrument and a `kind`. A `price` has signed integer `ticks` in millionths, with an absolute maximum of 2,000,000,000,000,000. A `time` has integer `time` in UTC Unix seconds, in years 0001 through 9999. Version 32 requires at least one `ray` or `trend`. A `ray` has a `start` endpoint. A `trend` also has a distinct `end` endpoint. Each endpoint has `time` and `ticks` within the same bounds. Version 33 requires at least one `rectangle` or `channel`. A `rectangle` has `start` and `end` corners with different times and prices. A `channel` has endpoints with different times and a nonzero signed integer `offsetTicks` for the parallel edge. Both prices shifted by that offset must stay within the price bounds. Version 34 requires at least one `polyline` or `fibonacci`. A `polyline` has a `points` array of three or more endpoints, in drawing order, with no identical consecutive entries. A `fibonacci` has `start` and `end` endpoints with different times and prices. Version 35 requires at least one `ellipse` or `triangle`. An `ellipse` has two opposite corners in `start` and `end` with different times and prices. A `triangle` has exactly three noncollinear endpoints in `points`. Version 36 requires at least one `note` or `arrow`. A `note` has a `start` endpoint and nonblank one-line `text`. An `arrow` has distinct `start` and `end` endpoints and points toward its end. Version 37 requires at least one `price-range` or `time-range`. Both have ascending `lower` and `upper` bounds. A price range stores integer ticks and a time range stores integer UTC seconds. |
| `manifest.series` | Imported history records. A record contains `id`, `descriptor`, `csv`, `barCount` and `sha256`. Each ID must match its canonical `VENUE:SYMBOL` and be unique across imported and built-in instruments. |
| `descriptor` | Version `1` plus the strings `venue`, `symbol`, `barInterval`, `source`, `usageGrant` and `adjustmentPolicy`. Older imports use their filename as source. Unknown legacy metadata is recorded as `unspecified`. |
| `manifest.seriesCount`, `manifest.barCount` | Number of imported histories and total number of data rows parsed by the Rust financial core. |
| `sha256` | A lowercase hexadecimal SHA-256 digest of the canonical manifest. It also covers the per-series digests. |

To reproduce a digest, recursively sort object keys by UTF-16 code unit, retain array order, encode JSON strings using ECMAScript JSON escaping, write safe integers in decimal, and omit formatting whitespace. Hash the UTF-8 encoding of that representation. A per-series digest covers the record after removing its `sha256` member. The sample digest covers objects with `id`, `name` and `bars`, in built-in catalog order. Each bar is an array of Unix seconds followed by open, high, low, close and volume in integer millionths.

Raw CSV text preserves its line endings, timestamps and precision in the backup. On restore the native-equivalent Rust/Wasm parser validates every row again. The per-file deployment limits for *new CSV imports* do not hide previously accepted histories in backups. The core's data bounds and the destination's browser storage quota still apply.
